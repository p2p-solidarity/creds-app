# 13 — F-Droid build (plan 2026-11-03, built 2026-11-03)

Status: **built** on branch `claude/fdroid-flavor-297c83` — the `fdroid` Android
flavor, Google-free release classpath, distribution capability flags. Evidence:
`docs/e2e/2026-11-03-fdroid-flavor/result.md`. Not done yet: the in-app QR
scanner replacement, fastlane metadata, the fdroiddata recipe and the
`fdroid scanner` pass (see "Still open").

Goal: ship creds.id on F-Droid without forking the app — one codebase, an
`fdroid` Android flavor that drops every non-free dependency, with each affected
feature degrading honestly (hidden or replaced, never a dead button).

## What F-Droid rejects

Inventory from the Android `build.gradle` of every native module (2026-11-03):

| Dependency (non-free) | Pulled in by | Feature it backs | In `fdroid` |
|---|---|---|---|
| `com.android.billingclient:billing` (via openiap) | `expo-iap` | Pro purchase (09-plan) | module excluded; paywall + Plan row hidden |
| `com.google.android.gms:play-services-auth` | `@react-native-google-signin/google-signin` | Google Drive backup (`src/backup/googleAuth.ts`) | module excluded; cloud backup screen hidden |
| `androidx.credentials:credentials-play-services-auth` | `nitro-modules/keystone` (`HybridPasskeyPrf.kt`) | Passkey PRF root vault (08-plan) | dependency dropped; every passkey surface hidden |
| `com.google.mlkit:text-recognition` | `nitro-modules/attest` | Passport MRZ OCR | dependency dropped; `HybridMrzOcr` stub; passport details typed by hand |
| `com.google.mlkit:barcode-scanning`, `play-services-code-scanner`, `play-services-mlkit-document-scanner` | `expo-camera` | QR scanner (`src/scan/QrScanner.tsx`) | module excluded; scanner entries hidden (replacement still open) |
| `com.google.firebase:firebase-messaging` | `expo-notifications` (config plugin only — no runtime import in `src/`) | none in use | module excluded |

F-Droid builds from source with its own signing key, so the `assetlinks.json`
on creds.id must list the F-Droid signing cert too, or App Links fail (see
memory: Android passkey assetlinks). Passkeys are off in `fdroid`, so only App
Links are affected.

## Product decisions (Kidney, 2026-11-03)

1. Pro on F-Droid: the **page-design** part is free (appearance controls, Pro
   blocks); every other Pro feature (notary witness / license, 09-plan) stays
   off and the paywall is hidden. `isPro` stays honest — the unlock is a
   separate `designUnlockedByDistribution` input that `useProGate` reads.
2. Passkeys on F-Droid: dropped. The recovery phrase is the backup path.
3. The rest of the non-free stack goes too.

Implementation choice (not a product decision, reversible): instead of hiding
the whole passport flow, `fdroid` hides only the MRZ camera scan — the manual
MRZ entry and the NFC chip read (jmrtd, free) need no ML Kit, and the passport
is the only distinct-person proof. The manual form says the camera scan is not
in this build (`passportSetup.details.noScanInBuild`).

MRZ OCR without ML Kit (Kidney, 2026-11-03): **no replacement — typing it is
the trade-off.** BAC needs only document number, birth date and expiry. Free
engines were weighed and rejected: Tesseract (OCR-B traineddata) is far slower
than ML Kit per frame; PaddleOCR/ONNX adds a runtime and models for one form;
a custom MRZ-only recogniser is a research project. The TD3 parser and check
digits in `src/mlkit/.../HybridMrzOcr.kt` are engine-independent if this is
ever revisited.

## How it works

1. **One switch: `EXPO_PUBLIC_CREDS_DISTRIBUTION=fdroid`**, read by Gradle and by
   Metro.

   ```bash
   cd apps/expo && bunx expo prebuild --platform android --no-install
   cd android && EXPO_PUBLIC_CREDS_DISTRIBUTION=fdroid ./gradlew assembleFdroidRelease
   ```

2. **`plugins/withFdroidFlavor.js`** (android/ is regenerated by prebuild, so
   nothing is hand-edited) patches:
   - `settings.gradle`: with the variable set, the modules above go into
     `expoAutolinking.exclude` and into `--exclude` of the React Native
     autolinking command; `gradle.ext.credsFdroid` tells the nitro modules to
     drop their own non-free dependencies. A marker file joins React Native's
     autolinking cache key so switching distribution re-runs autolinking.
     Asking for an fdroid task without the variable fails at configuration.
   - `app/build.gradle`: the `fdroid` product flavor (and `debuggableVariants`)
     exists only in an F-Droid run. The Play build keeps its flavorless
     variants, so `bundleRelease`, `expo run:android` and the Play submit
     recipe are untouched.

   Why not two always-on flavors: Expo autolinking resolves one module list per
   Gradle run and adds every module to the `expo` project, so a single run
   cannot link `expo-iap` for `play` and not for `fdroid`. A run builds one
   distribution.
3. **Metro** swaps the excluded packages for `plugins/fdroidUnavailableModule.js`
   when the variable is set: their JS looks the native module up on import
   (`getEnforcing` / `requireNativeModule`), which would crash at launch.
   Calling any export of the stand-in throws.
4. **`src/platform/distribution.ts`** is the one module screens read:
   `capabilities.{proPurchase, designUnlockedByDistribution, passkeys,
   cloudBackup, passportScan, qrScanner}`. Nothing checks the distribution
   string directly. Routes for hidden features (`/settings/pro`,
   `/settings/passkeys`, `/settings/backup`, `/scan`) redirect.

## Still open

- **QR scanner** in `fdroid`: swap `expo-camera` barcode for VisionCamera (already
  linked) + a free decoder — ZXing core (Apache-2.0, accepted by F-Droid) behind
  a new `attest` Nitro method on a VisionCamera frame. Needs a real camera run.
  Until then people add a contact by name, by hand or by opening a creds.id link
  (the system camera app scans the QR).
- **Metadata.** `fastlane/metadata/android/<locale>/` (title, descriptions,
  screenshots, changelogs per versionCode) and the fdroiddata `Builds:` block
  (`prebuild`, the env variable, `gradle: [fdroid]`, `rm` of the excluded
  packages' sources so `fdroid scanner` passes on the tree).
- **Anti-features:** `NonFreeNet` (creds.id directory; Nostr relays are fine);
  `Tracking` none — no analytics SDK is linked in the fdroid classpath.
- `assetlinks.json` entry for the F-Droid signing cert (App Links).
